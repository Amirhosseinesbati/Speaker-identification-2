# ساخت و ارزیابی بستهٔ منتخب CAM++

P002 روش منتخب را از یک آزمایش کاملاً پایان‌یافته می‌گیرد. تنظیمات `configs/package/campp_selected.json` به گزارش مستقل، export، commit و تمام اجرای والد/فرزند با SHA متصل می‌شود. انتخاب روش و کالیبراسیون نهایی دو مرحلهٔ جدا هستند؛ مقدار کالیبراسیون نهایی، OOF یا امتیاز لیدربرد نیست.

| روش منتخب | مدل‌های مجاز | پرسش‌های کالیبراسیون نهایی |
|---|---|---|
| S006f | encoder آموزش‌دیدهٔ F004، فولد صفر | ۹۹۹ پرسش اصلی Q0 |
| S007b | CAM++ عمومی ۱۹۲بعدی | ۴۴۴۰ فایل قابل استفاده |
| S008c | ترکیب CAM++ عمومی ۵۱۲ و ۱۹۲بعدی | ۴۴۴۰ فایل قابل استفاده |
| S009d | ترکیب F004 فولد صفر با CAM++ عمومی ۱۹۲بعدی | ۹۹۹ پرسش اصلی Q0 |

انتخاب فولد صفر پیش از نتیجهٔ S009 ثابت شده است. در کالیبراسیون، کل گروه محتوای پرسش از هر دو مجموعهٔ مرجع شناخته‌شده و ناشناخته حذف می‌شود. برای استنتاج، همهٔ ۲۲۱۷ مرجع شناخته‌شده و ۲۲۲۳ مرجع ناشناختهٔ مجاز برگردانده می‌شوند. در روش‌های ترکیبی، وزن فقط از مجموعهٔ ثابت ۰، ۰٫۲۵، ۰٫۵، ۰٫۷۵ و ۱ با دادهٔ کالیبراسیون انتخاب می‌شود. اگر انتخاب endpoint باعث حذف یک مدل شود، مجموعهٔ پرسش‌های مجاز و سابقهٔ روش همان می‌ماند؛ کالیبراسیون دومی روی پرسش‌های بیشتر انجام نمی‌شود.

ساخت فقط روی instance 50079023 پس از دریافت کد از Git، آمادگی متناظر با commit و کنترل زندهٔ MLflow انجام می‌شود:

```bash
.venv/bin/python scripts/package_selected.py --config configs/package/campp_selected.json
bash scripts/infra/install_experiment_supervisor.sh P002
supervisorctl start speaker_id_campp_p002
```

دستور اول فقط schema تنظیمات را بررسی می‌کند. Supervisor شروع و راه‌اندازی دوبارهٔ خودکار ندارد. ساخت واقعی، داده‌ها، شواهد منابع و وزن‌ها را بررسی می‌کند، آرتیفکت‌های مرجع MLflow را بازمی‌خواند و بسته را در یک اجرای جدید ثبت می‌کند. هیچ آموزش encoder یا استخراج دوبارهٔ embedding در ساخت انجام نمی‌شود. اگر F004 لازم باشد، فقط state خود encoder صادر می‌شود؛ classifier و optimizer داخل ZIP نیستند.

ZIP شامل `submission.py` در ریشه، کد مستقل inference، وزن‌های لازم، مرجع‌ها، تنظیمات و manifest است. وابستگی اجرایی آن Python 3.12، NumPy، SciPy، SoundFile، Torch و Torchaudio است؛ نسخه‌های آزمون باید داخل بازه‌های `Competition-Guide/leaderbordpakage.txt` باشند. دانلود مدل و وابستگی به MLflow یا checkout در استنتاج وجود ندارد.

```bash
python submission.py --data-dir INPUT_DIRECTORY --predictions-file-path OUTPUT.csv
```

خروجی ستون‌های `audio_file,speaker_id` دارد. فایل صفر و فایل غیرقابل decode به `unknown` می‌روند. شکست بارگذاری مدل اجرای بسته را ناموفق می‌کند و خروجی قبلی حفظ می‌شود. فایل ورودی، وزن یا کد بسته قابل بازنویسی به‌عنوان خروجی نیست.

پیش از تحویل، ZIP واقعی بیرون checkout و با cache خالی استخراج می‌شود و هفت صوت نماینده شامل MP3/WAV، صفر، کوتاه، بلند، چندکاناله و نرخ نمونه‌برداری متفاوت روی CPU و CUDA بررسی می‌شوند. آزمون CPU:

```bash
python scripts/checks/check_selected_release_offline.py --build-dir artifacts/releases/P002_ACTUAL_ID --report artifacts/infrastructure/P002_verification/offline_qa.json --execute
```

پوشهٔ واقعی ساخته‌شده جایگزین `P002_ACTUAL_ID` می‌شود. گزارش‌ها هش ZIP، خروجی‌ها، اختلاف با cache معتبر، جلوگیری از شبکه و وضعیت اجرای MLflow را ثبت می‌کنند. موفقیت این بررسی‌ها سازگاری محیط آزمون را نشان می‌دهد؛ تصویر دقیق داور و دادهٔ پنهان در اختیار پروژه نیست. نسخهٔ پیشین P001 محفوظ می‌ماند و ارسال لیدربرد را کاربر انجام می‌دهد.
